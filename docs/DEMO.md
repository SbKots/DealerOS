# Демонстрация DealerOS 0.3–0.7

## Сценарий визита и Offer

1. Пройдите для demo-автомобиля утверждение плана, execution, QC и подготовку Listing до `Ready`.
2. В CRM создайте Customer и Lead на этот автомобиль, назначьте менеджера, зафиксируйте meaningful contact и квалифицируйте Lead.
3. В разделе «Продажи» запланируйте визит, отметьте прибытие, выдачу/возврат test-drive автомобиля и завершите визит с результатом.
4. Сформируйте Offer. Preview с сервера показывает публичную цену, строки, скидку, snapshot себестоимости, ожидаемую маржу и необходимость manager decision.
5. Отправьте Offer. Для проверки независимого согласования создайте его пользователем `manager@volga-auto.demo`, а решение примите `admin@volga-auto.demo`.
6. Убедитесь, что Approved Offer доступен только для чтения, сохраняет snapshot, а изменение создаёт Draft-ревизию.

1. Запустить `docker compose up --build`, открыть `http://localhost:4173`.
2. Войти `admin@volga-auto.demo` / `DealerOS!2026`.
3. Заполнить уникальный валидный VIN, марку, модель, год, пробег и цену.
4. Создать поступление: карточка показывает `Черновик`; повтор того же VIN даст понятный conflict.
5. Нажать «Принять на склад»: появятся `На складе` и номер `MSK-YYYY-XXXXXXXX`.
6. Обновить страницу: запись сохранена в PostgreSQL.
7. Выйти и войти как `admin@north-auto.demo`: автомобиль первой организации не виден и прямой URL возвращает 404.

Проверяемые эффекты: status history содержит два перехода, audit — `vehicle.intake_created` и `vehicle.accepted_to_stock`, оба события имеют actor, tenant и correlation ID.

## Сценарий осмотра

1. Войти `inspector@volga-auto.demo` / `DealerOS!2026` и открыть «Осмотры».
2. В очереди выбрать demo Lada Vesta с VIN `XTA210990Y0200001`, начать осмотр.
3. Заполнить 11 пунктов; прогресс должен достичь 100%.
4. Добавить Critical-дефект тормозов, выключив client checkbox блокировки. Сервер всё равно включит `RepairRequired` и `BlocksSale`.
5. Прикрепить PNG/JPEG/WebP до 8 МБ, увидеть preview. MinIO bucket остаётся приватным.
6. Завершить осмотр с подтверждением: автомобиль перейдёт в `ReconditioningRequired`.
7. Обновить страницу, в карточке автомобиля открыть вкладку «Осмотры»: ревизия, дефект и фото доступны read-only.

Для tenant negative check войти как `admin@north-auto.demo`: осмотр и фото «Волга Авто» недоступны и прямые API URL возвращают 404.

## Сценарий подготовки и бюджета

1. Войти `prep@volga-auto.demo` / `DealerOS!2026`, открыть «Подготовка».
2. Выбрать demo Lada XRAY `XTA210990Y0200002`: Completed inspection уже содержит обязательный дефект бампера.
3. Создать план. Дефект автоматически появляется как mandatory work, бюджет — 32 000 RUB.
4. Изменить исполнителя, labor/parts и срок; добавить и удалить дополнительную работу. Удаление последней mandatory work потребует причину.
5. Отправить план руководителю. Поля становятся read-only.
6. Выйти и войти `manager@volga-auto.demo`; в очереди согласований открыть план.
7. Указать лимит и утвердить. Система сохраняет immutable snapshot плановой суммы и лимита.
8. Снова войти `prep@volga-auto.demo`, открыть последний Approved и создать новую ревизию. Сравнение показывает состав и бюджет rev. 1 → rev. 2; исходный Approved не меняется.

Дополнительные проверки: автору с approve permission запрещено утвердить собственный план; `admin@north-auto.demo` получает 404 на чужой plan ID; повтор одного decision ID безопасен.
