# Допущения итерации 0.3

Реальные интервью с мастером подготовки и руководителем площадки пока недоступны. Решения ниже подходят для локальной демонстрации и должны быть проверены на пилотном автосалоне до production.

1. План создаётся только из Completed inspection автомобиля в `ReconditioningRequired`; источник выбирается явно и проверяется сервером.
2. `RepairRequired` означает обязательное включение дефекта. Последнюю работу по такому дефекту можно удалить только с причиной; причина остаётся в plan history и audit.
3. Любая добавленная работа обязана ссылаться на дефект исходного осмотра. Полностью профилактические работы без дефекта будут отдельным расширением после интервью.
4. Оценка дефекта переносится в labor, parts стартуют с нуля. Пользователь обязан уточнить разбивку до submit.
5. Один work использует одну валюту. Read model показывает валюты раздельно, а submit блокирует mixed-currency план.
6. План пустой после всех исключений нельзя отправить даже при наличии причин исключения.
7. Активными считаются `Draft`, `Submitted`, `ChangesRequested`; Approved/Rejected/Cancelled остаются историей. На автомобиль допускается только одна активная ревизия.
8. ChangesRequested редактируется в той же ревизии и повторно отправляется. Approved меняется только новой ревизией; Rejected/Cancelled может начать следующий нумерованный черновик из исходного осмотра.
9. Одобренный snapshot фиксирует labor, parts, requested total, approved limit, currency, руководителя и время. Он не меняется при создании следующей ревизии.
10. Настройка `RequireIndependentReconditioningApproval` включена по умолчанию и для demo. Отдельный UI управления настройкой вне scope 0.3.
11. Approval не меняет `VehicleStatus`: автомобиль остаётся `ReconditioningRequired`, пока 0.4 не выполнит работы и контроль качества.
12. `ReadyForSale` по-прежнему означает полную готовность после выполнения подготовки и QA, а не утверждение бюджета.

## Проверить на интервью

- можно ли добавлять профилактические работы без source defect;
- кто имеет право исключать обязательный дефект и нужен ли второй approval;
- допустимы ли несколько валют в одном плане при отдельных подрядчиках;
- календарная дата или длительность лучше отражает плановый срок;
- допустим ли approved limit ниже обязательного состава и кто принимает риск;
- кто может отменить Submitted plan и требуется ли уведомление руководителя;
- должен ли Rejected всегда создавать новую ревизию или возвращаться в ChangesRequested.
