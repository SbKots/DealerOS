# Итерация 0.7 — визиты, test drive и согласованное предложение

## Сквозной сценарий

Квалифицированный лид на автомобиль `ReadyForSale` проходит запланированный визит. Сотрудник отмечает прибытие, при необходимости выдаёт и принимает автомобиль для test drive по минимальному чек-листу, фиксирует результат и следующее действие. После завершённого визита менеджер формирует предложение из публичной цены, прозрачных положительных строк и скидки. Сервер рассчитывает итог, snapshot подтверждённой себестоимости и ожидаемую маржу. Предложение либо автоматически утверждается в пределах полномочий, либо проходит независимое решение руководителя. Утверждённые значения сохраняются неизменяемым snapshot; изменения выполняются новой ревизией.

## Инварианты

- tenant и branch определяются и проверяются сервером; Customer, Lead, Vehicle и ответственный сотрудник должны принадлежать одному контексту;
- визит создаётся только для `Qualified` lead с назначенным активным менеджером и автомобилем `ReadyForSale`;
- время хранится как UTC `timestamp with time zone`, конец строго позже начала;
- PostgreSQL exclusion constraints не допускают пересекающиеся активные слоты ответственного, а для test drive — того же автомобиля;
- lifecycle визита меняют отдельные команды: reschedule, arrive, check-out, check-in, complete, no-show и cancel;
- сохраняется только признак проверки водительских документов; сканы и полный номер документа не принимаются и не журналируются;
- Offer доступен только после завершённого визита и использует `Ready` listing, завершённое execution и подтверждённую себестоимость;
- строки предложения строго положительны, скидка неотрицательна, валюты совпадают, итог вычисляет сервер;
- предложение ниже минимальной маржи или выше лимита скидки нельзя молча утвердить автоматически;
- автор не может принять требующее руководителя решение по собственному Offer;
- решение идемпотентно только для того же decision ID и payload; optimistic concurrency и DB constraints оставляют один результат конкурентного согласования;
- `Approved` неизменяем; цена, себестоимость, маржа, срок, строки и лицо, утвердившее предложение, сохраняются в `ApprovedOfferSnapshot`;
- `Rejected`, `Expired` и `Cancelled` не могут использоваться как действующее утверждённое предложение.

## Права

- `sales.visits.view/create/edit/complete`;
- `sales.offers.view/create/edit/submit/auto_approve/approve/cancel`.

Менеджер продаж получает рабочие команды, а право независимого решения выдаётся руководителю. Проверки прав выполняются application service, branch scope повторно проверяется для каждого агрегата.

## Проверяемость

Unit-тесты покрывают переходы визита, test-drive guards, расчёт Offer, auto approval, независимое решение, неизменяемый snapshot и ревизию. PostgreSQL+MinIO integration test проходит полный путь от подготовки автомобиля до `Listing Ready`, CRM lead, конкурентного бронирования слота, test drive, Offer и конкурентного решения; отдельно проверяются преждевременный Offer, идемпотентный create, payload conflict и cross-tenant 404. Component tests покрывают календарь/выдачу автомобиля, серверный preview и read-only snapshot.

## Ограничения

В 0.7 нет Reservation, Deal, оплаты, договоров, выдачи автомобиля, PDF/подписи, интеграции с календарями и внешними каналами. Проверка документов — подтверждение сотрудника, не юридическая верификация. Версия предназначена только для локальной демонстрации и не готова к production.
