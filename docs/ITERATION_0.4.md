# Итерация 0.4 — выполнение подготовки

## Сквозной сценарий

Утверждённый `ReconditioningPlan` предоставляет неизменяемый budget snapshot. Сотрудник подготовки идемпотентно создаёт одно execution, начинает заказ-работы, фиксирует труд, материалы/возвраты и внешнего подрядчика, устраняет блокировки и завершает обязательные работы. Если факт выше лимита, завершение невозможно до отдельного решения руководителя. После урегулирования подрядчика и бюджета execution фиксируется как `Completed`.

## Инварианты

- execution создаётся только из `Approved` plan и ровно один раз на snapshot;
- tenant, branch и permission проверяются endpoint policy, application service и составными FK;
- утверждённый план и budget snapshot не изменяются;
- отрицательные суммы и смешение валют запрещены доменом и DB constraints;
- material movement и overrun decision идемпотентны по command ID;
- optimistic concurrency не допускает двух несовместимых результатов;
- обязательная работа, неподтверждённый перерасход и незакрытый внешний расчёт блокируют завершение;
- все критические команды записываются в `audit.audit_events` в той же транзакции;
- фоновые уведомления дедуплицируются по execution/work/type и не меняют пользовательские решения.

## Ограничения

0.4 не выполняет складской учёт запасов: material movement — финансово-операционный факт конкретной заказ-работы, а не резервирование общей номенклатуры. Контроль качества, `ReadyForSale`, публикация, CRM и продажи остаются последующими checkpoint release train. Версия предназначена для локальной демонстрации, не для production.
